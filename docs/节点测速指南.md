# Clash 节点测速完全指南：延迟怎么看、怎么选节点、测速失败怎么排查

> 本文是 [tanqingbo.cn](https://tanqingbo.cn/) 上《[Clash 节点测速完全指南](https://tanqingbo.cn/clash-node-testing/)》的完整版，聚焦一个高频动作——**测速**：延迟怎么来的、怎么测才准、测速失败和"数字好看但体感拉胯"怎么排查。

先泼一盆冷水：**你在 Clash 里点「测速」看到的那个毫秒数，根本不是"这个节点有多快"。** 它测的是时延，不是带宽——一个延迟只有 30ms 的节点，下载可能比延迟 200ms 的还慢。

很多人拿到订阅第一件事就是狂点测速，然后照着数字从低到高挑，结果还是卡。问题出在没搞懂测速到底在测什么。

## 一、测速测的到底是什么

Clash 里的「测速」，本质是向节点发出一个**小小的 HTTP 请求**，记录从发出到收到响应的往返时间，也就是**延迟（Delay / Latency）**，单位毫秒。

两个关键特点：

- **它测的是"路通不通 + 路有多远"，不是"路有多宽"**。一个测速请求可能只有几 KB，延迟低只能说明这条链路时延小，不代表传大文件时带宽高。
- **延迟和带宽是两个维度**。打游戏、视频会议看重延迟；下大文件、看高清看重带宽。两者经常不同步。

## 二、怎么测：客户端内置测速

以 Clash Verge Rev 为例：

1. 打开客户端，进入「代理」（Proxies）页
2. 找到要测的节点组（策略组），点组名右侧的「测速」按钮
3. 客户端会向组内每个节点发测速请求，几秒后显示延迟数字，**越小表示时延越低**

也可以勾选多个节点后批量测速，或右键单个节点单独测。Android（ClashMetaForAndroid）、iOS（Stash）等操作大同小异，都是在节点列表里找「测速 / 全部测速」。

读数字时结合两个信息一起判断：

- **延迟数值**：100ms 以内体验很好，100–200ms 日常可接受，300ms 以上卡顿明显
- **波动**：同一节点多测几次，如果忽高忽低（一会 80ms 一会 400ms），说明线路不稳——**比一直稳定在 200ms 更难受**

## 三、自动选最快：url-test

手动一个个点太麻烦，用 `url-test` 策略组可以自动测速、自动切到延迟最低的节点：

```yaml
proxy-groups:
  - name: "🚀 自动选择"
    type: url-test
    proxies: [节点A, 节点B, 节点C, ...]
    url: "https://www.gstatic.com/generate_204"
    interval: 300   # 每 300 秒测一次并切换
```

配置说明：

- `type: url-test` 让组内周期测速，自动选延迟最低的节点
- `url` 是测速地址，选稳定、不消耗大流量的目标
- `interval` 是测速间隔（秒）。设太短会频繁发测速请求，节点多时流量和后台开销都不小，**300 秒是常见平衡点**

`url-test` 适合"只想稳、不在乎落地地区"的场景。如果需要固定地区（比如看奈飞要锁定某区），还是用 `select` 手动选更合适——测速只是帮你判断哪个顺，不是越自动越好。

## 四、测速地址（URL）怎么选

测速用哪个地址，直接决定数字可不可信：

- **用「返回即走」的轻地址**：Google 的 `gstatic.com/generate_204`（返回 204 空响应）、Cloudflare 的 `cp.cloudflare.com`。不加载大内容，测速快、不费流量
- **别用大文件页**：拿 speedtest 那种要下几 MB 的地址做分组自动测速，每 5 分钟一次、几十个节点一起跑，流量哗哗的
- **国内直连节点用国内地址**：想测国内直连的节点却用境外地址，数字会失真，换 `connect.rom.miui.com/generate_204` 这类国内可达地址
- **机场自带测速地址**：很多订阅自带 `url` 配置，直接用就行，通常是针对它们自己线路优化的

有个细节值得留意：Mihomo 的测速请求可以用 `headers` 指定 `User-Agent`，**部分节点对空 UA 或默认 UA 会返回异常**，导致本可用的节点被判"超时"。如果发现大批节点测速失败但实际能连，试着给测速配置加一个正常的浏览器 UA——这是排查"全灭但网络其实通"时最容易忽略的一环。

## 五、测速失败 / 延迟高怎么排查

### 5.1 测速失败、报错误码或超时

先判断是「单个失败」还是「全灭」。

**单个节点失败** —— 多半是节点自身问题：挂了、入口被墙、机场临时下线。直接换一个，别纠结。

**全部节点都失败 / 报 443** —— 按顺序查：

1. **代理是不是真在生效**。确认系统代理开关是开的，或 TUN 已开启。有时候关了代理却去测速，当然全失败
2. **测速 URL 被阻断**。某些网络环境会针对测速地址做干扰，换成 `cp.cloudflare.com` 再试
3. **订阅过期 / 节点信息失效**。机场节点会定期更换地址和密码，订阅没更新时拿到的是一堆失效节点，重新拉一次订阅
4. **DNS 异常**。解析失败也会让测速请求发不出去，检查 DNS 配置或重启客户端清缓存
5. **测速请求的 UA 被拒**。见上一节，加一个正常的浏览器 UA
6. **错误码 443**。通常和 HTTPS 测速目标不可达有关（节点能连但握手失败，或目标被 RST）。换个测速 URL、换个节点基本能绕开

### 5.2 延迟很高，或数字好看但实际卡

**延迟确实高**（300ms+，体感也卡）——大概率是链路问题：

- 本地到节点入口的距离占时延大头，落地离你越远延迟越高，先换近的节点
- **协议不合适**：Reality、Hysteria2 在弱网、跨网场景下通常比老协议（SS、老 VMess）表现好
- **多重代理叠加**：系统级代理 + Clash 又开一层，等于绕两趟，延迟直接翻倍

**延迟很低但实际卡**（数字好看，体感拉胯）——延迟和带宽脱节了：

- **出口带宽被限**：延迟 50ms，但出口限到 2 Mbps，看视频当然卡
- **链路丢包**：延迟低但丢包严重，TCP 来回重传，感受比高延迟还差
- **高峰期拥堵**：白天测速时线路空闲，晚上高峰出口塞满，延迟没变但带宽塌了

判断真实速度要**跑一次真实下载**：用 speedtest 测一次，或开个大文件下载看实际速度。延迟是"路况"，下载速度才是"车能跑多快"。

## 六、怎么按延迟挑节点（实操）

把上面的串起来，选节点按这个顺序：

1. **先看延迟过滤掉离谱的**：排除 300ms 以上、或测速一直失败的节点
2. **再看波动**：多个低延迟节点里，挑数字稳的
3. **按用途定策略**：
   - 打游戏、开会 → 用 `url-test`，自动选低延迟
   - 看流媒体、下大文件 → 手动选固定节点，重点看实际下载速度而非延迟
   - 有地区要求（奈飞某区）→ 锁定该区节点，测速只用来挑该区内最稳的
4. **别迷信最低那个**：延迟 30ms 的节点若出口限速，不如 80ms 但带宽充足的

一个容易忽略的点：**测速结果受当前模式影响**。全局模式下所有流量走代理，数字反映节点真实链路；规则模式下如果测速域名恰好命中直连规则（比如用国内测速地址测境外节点），数字就会失真。测速前先确认模式。

## 七、常见问题

**Clash 怎么测速节点延迟？**

打开客户端「代理」页，选中节点组后点「测速」，客户端会向每个节点发测速请求并显示延迟（毫秒）。也可勾选多个节点批量测。延迟低通常快，但延迟低不等于带宽高。

**延迟多少算好？**

100ms 以内体验很好，100–200ms 日常可用，300ms 以上明显卡顿。它反映的是到节点的网络时延，不是出口带宽。

**测速失败、报 443 或超时怎么办？**

先分清单个还是全部。单个失败换节点即可；全部失败检查：系统代理 / TUN 是否开启、测速 URL 是否被阻断、订阅是否过期、DNS 是否异常、UA 是否被拒。443 常和 HTTPS 目标不可达有关，换个测速地址通常能解决。

**为什么延迟很低，实际却很慢？**

延迟与带宽脱节。测速只发小请求，不代表大流量下的带宽；出口带宽被限、链路丢包、高峰拥堵都会让下载变慢。跑一次真实下载才准。

**为什么很多节点测速都失败，但我其实能上网？**

大概率是测速请求被拒，不是网络断了。两个高发原因：一是测速 UA 为空或默认值，部分节点会拒掉，加个正常浏览器 UA 即可；二是当前是规则模式，测速域名恰好命中直连规则，数字失真或请求走错路由。

**哪个测速地址比较准？**

推荐稳定的境外 HTTP(S) 服务：`gstatic.com/generate_204`、Cloudflare 的 `cp.cloudflare.com`，或机场自带的测速地址。别用大文件地址做自动测速。国内直连节点用 `connect.rom.miui.com/generate_204`。

**节点延迟一直很高怎么排查？**

按顺序：确认选的是落地离你近的节点；换协议（Reality、Hysteria2 在弱网下常优于老协议）；检查是否叠了多重代理；用 ping 或 tracert 看是本地问题还是节点问题；联系机场换线路。延迟主要由物理距离和线路质量决定，不是本地配置能硬调下来的。
