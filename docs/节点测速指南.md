# Clash 节点测速完全指南：延迟怎么看、怎么选节点、测速失败怎么排查

> 本文是 [tanqingbo.cn](https://tanqingbo.cn/) 上《[Clash 节点测速完全指南](https://tanqingbo.cn/clash-node-testing/)》的精选版，保留最核心的「延迟 ≠ 带宽」认知与排查逻辑。

先泼一盆冷水：**你在 Clash 里点「测速」看到的那个毫秒数，根本不是"这个节点有多快"。** 它测的是时延，不是带宽——一个延迟只有 30ms 的节点，下载可能比延迟 200ms 的还慢。

## 测速测的到底是什么

测速是向节点发一个**小小的 HTTP 请求**，记录往返时间，也就是延迟（Delay），单位毫秒。两个要点：

- 它测的是"路通不通 + 路有多远"，不是"路有多宽"
- 延迟和带宽是两个维度：打游戏看延迟，下大文件看带宽

## 延迟参考

- 100ms 以内体验很好
- 100–200ms 日常可接受
- 300ms 以上明显卡顿
- 同一节点多次测忽高忽低（如 80ms↔400ms），说明线路不稳定

## 自动选最快：url-test

```yaml
proxy-groups:
  - name: "🚀 自动选择"
    type: url-test
    proxies: [节点A, 节点B, 节点C, ...]
    url: "https://www.gstatic.com/generate_204"
    interval: 300   # 每 300 秒测一次并切换
```

## 测速失败怎么排查

**单个节点失败** → 节点挂了或入口被墙，直接换节点。

**全部节点都失败 / 报 443** → 按顺序查：

1. 代理是否真在生效（系统代理 / TUN）
2. 测速 URL 是否被阻断（换个地址）
3. 订阅是否过期、节点是否失效
4. DNS 是否异常
5. 测速请求 UA 是否被拒（补一个正常浏览器 User-Agent）
6. 错误码 443 通常和 HTTPS 目标不可达有关，换测速地址或节点

## 延迟低但实际卡

这是延迟和带宽脱节了：出口带宽被限、链路丢包、高峰期拥堵。判断真实速度要**跑一次真实下载**（speedtest 或大文件），别只看毫秒数。
